# Паспорт Лавки

Профиль правил: E3

## Что делает сервер

По контракту Лавка показывает каталог, цену и остатки отдельного товара, баланс участника и статус заказа. Вызовы чтения сохраняют данные в прежнем состоянии. При покупке сервер создаёт заказ, списывает коины и уменьшает остаток. При отмене он возвращает товар и коины один раз. Подтверждение выдачи меняет только статус заказа.

При отмене возвращается 90% сохранённой стоимости с округлением вниз. Товар возвращается полностью.

## Границы

Лавка работает локально с учебными пользователями, заранее внесёнными в базу. Клиент передаёт `user_id`. Сервер проверяет, есть ли такой пользователь, без проверки его личности. Настоящие платежи, доставка и изменение каталога через MCP не поддерживаются.

## Путь запроса

`client.py` → `mcp_adapter.get_product` → `read_handlers.get_product` → `Storage.get_product` → `SELECT` из `products` и `stock` → `success(product)` или `failure("PRODUCT_NOT_FOUND", "Товар не найден")`.

## Проверка отказа

На свежей учебной базе вызываем `create_order` с аргументами `{"user_id":"student_poor","product_id":"hoodie","size":"M","quantity":1}`. Худи стоит 500 коинов, на балансе участника 20.

Сервер возвращает `INSUFFICIENT_COINS`. `src/order_handlers.py` вызывает `domain.purchase_error` перед записью заказа. Проверка баланса идёт после проверки пользователя, товара, размера, остатка и лимита.

Тест `test_insufficient_coins_changes_no_table` сверяет содержимое `products`, `stock`, `users` и `orders` до и после отказа.

## Подключение другого клиента

Команда запуска из корня проекта — `python3 -m src.server`. Транспорт — `stdio`. Клиент запускает сервер отдельным процессом и обменивается MCP-сообщениями через стандартные потоки.

- Контракты инструментов — `contracts/tools_schemas.json`.
- Команды запуска и проверки — `RUN.md`.
- Журнал аргументов и ответов штатного клиента — `logs/client.jsonl`.
- Учебная база ручных вызовов — `data/lavka.db`. Для отдельной базы передайте серверу `--db`.
